# 代偿补偿审批表引用能力方案

## 目标

在“代偿补偿审批表预览”中，为关键数据增加可追溯引用。

用户在鼠标悬停到数据上时，可以看到：

- 来源文件名
- 文件相对路径
- 对应字段
- 取值说明
- 如为程序计算项，则显示计算公式

第一阶段只覆盖“确定性字段”，不让模型猜来源。

## 为什么不能直接让 LLM 自己带来源

当前审批表生成链路中，LLM 接收到的是结构化缓存数据，而不是原始 Excel/PDF 文件集合。

因此，LLM 现在知道：

- 社会统一信用代码的值
- 借款合同号的值
- 补偿金额的值

但它并不知道这些值具体来自：

- 哪个原始文件
- 哪个字段
- 是否包含程序计算公式

所以，如果不先在缓存层保存来源信息，LLM 只能猜来源，结果不可追责。

## 第一阶段实现原则

1. 来源信息在生成案件缓存时同步产出
2. 报告生成时直接复用缓存中的来源信息
3. 只给“确定性字段”增加引用
4. 不要求 LLM 输出来源，来源由程序后处理挂载

## 数据流改造

### 1. 案件缓存层增加来源映射

在 `case-analysis.ts` 中，除了现有的 `keyFacts` 外，新增 `factSources`。

示意结构：

```ts
type FactSource = {
  sourceId: string;
  label: string;
  fileName: string;
  relativePath: string;
  kind: 'xlsx' | 'pdf' | 'derived';
  sheet?: string;
  field?: string;
  excerpt?: string;
  formula?: string;
};

type FactSourceMap = Record<string, FactSource[]>;
```

缓存生成时，程序在从 Excel 行中取值的同时，把来源一起写进 `factSources`。

例如：

- `unifiedCode`
- `businessNo`
- `contractNo`
- `guaranteeNo`
- `entrustNo`
- `compensationDate`
- `uncompensatedPrincipal`
- `indemnityAmount`
- `reGuaranteeRatio`
- `compensationAmount`

其中：

- 直接取值字段，记录 `file + sheet + field`
- 计算字段，记录 `file + field + formula`

### 2. 审批表结构增加引用元数据

在 `GeneratedCompensationReport` 中新增：

```ts
type CitationSource = FactSource;

type CitationMap = Record<string, string[]>;
```

并新增两个字段：

- `sourceCatalog`
- `citations`

其中：

- `sourceCatalog` 存放所有可用来源详情
- `citations` 存放“报告字段路径 -> sourceId[]”映射

示例：

```ts
{
  sourceCatalog: {
    compensationAmount: {
      sourceId: 'compensationAmount',
      fileName: 'tmp解保台账数据_1772421102442.xlsx',
      relativePath: 'tmp解保台账数据_1772421102442.xlsx',
      kind: 'derived',
      field: '债务人未清偿本金（含债权人部分）（万元）',
      formula: '债务人未清偿本金（含债权人部分）（万元） × 10000 × 0.4'
    }
  },
  citations: {
    'sections.riskRows.0.compensationAmount': ['compensationAmount']
  }
}
```

### 3. 审批表生成后做后处理挂引用

LLM 仍只负责生成审批表正文结构。

在 `compensation-approval-report.ts` 中：

1. 调用 LLM 生成 `structured`
2. 根据 `analysis.factSources` 构建 `sourceCatalog`
3. 根据审批表字段内容，给关键字段挂 `citations`
4. 最终缓存带引用的 `GeneratedCompensationReport`

## 第一阶段覆盖范围

第一阶段只做以下字段：

### 表头

- 担保机构名称
- 日期

### 借款情况表

- 债权人
- 主债权金额
- 借款合同号
- 保证合同号
- 委保合同号
- 主债权起始日期
- 主债权到期日期

### 分险比例与分险金额表

- 代偿时间
- 债务人未清偿本金
- 原担保机构代偿金额
- 省级再担责任比例
- 省级再担代偿补偿金额

### 关键段落

先按“段落级引用”做最小实现：

- 债务人基本情况中包含统一社会信用代码的段落
- 备案情况中包含业务编号/合同号的段落
- 结论中包含补偿金额的段落

## 前端展示方案

在 `CompensationApprovalPreviewClient.tsx` 中新增统一渲染组件：

- `CitationValue`

行为：

1. 如果字段没有引用，按普通文本渲染
2. 如果字段有引用：
   - 文本加点状下划线
   - `title` 显示来源摘要
   - 后续可升级为自定义 Tooltip

Tooltip 文案示例：

```text
来源文件：tmp解保台账数据_1772421102442.xlsx
字段：债务人未清偿本金（含债权人部分）（万元）
取值说明：来源于解保台账最新记录
计算公式：债务人未清偿本金（含债权人部分）（万元） × 10000 × 0.4
```

## 为什么先做确定性字段

因为这些字段具备三个特点：

1. 来源明确
2. 不依赖模型猜测
3. 用户最关心

这样可以先把“关键金额和编号可追溯”做扎实。

## 第二阶段

第二阶段再处理“AI 生成段落的多来源引用”。

那一阶段才考虑：

- 给 LLM 输入 `value + source`
- 要求它输出段落时顺带返回 `sourceId`
- 或者程序在生成后对段落做更细的引用匹配

但这不应放在第一阶段。

## 本次实现范围

本次代码实现只覆盖：

1. 缓存层增加 `factSources`
2. 审批表结果增加 `sourceCatalog + citations`
3. 审批表预览页支持 hover 查看来源
4. 只覆盖第一阶段字段
